# 图片素材与导出容量

本参考仅处理 Next AI Draw.io MCP 的素材预处理、传输容量、保存和导出，不规定构图、美化或视觉风格。插入图片、处理大文件、遇到容量错误或导出超时时按需读取。

## 操作边界

- 预处理被嵌入的图片素材时创建副本，不覆盖用户原图。按实际需要降低体积，保留宽高比，检查处理后的尺寸、字节数和内容。
- 照片可以适度有损压缩；文字、细线及透明素材优先保真，保留需要的透明通道。照片中含有这些内容时，也按内容保真要求处理。不要为达到某个任意文件大小反复降低质量。
- 优先使用当前环境已有的处理工具；没有可用工具时说明缺项，不自动安装软件或依赖。
- 图表的创建、修改和最终文件输出均通过 MCP；`.drawio`、`.png`、`.svg` 和 `.drawio.svg` 通过 `export_diagram` 输出。素材预处理不授权用脚本、其他绘图程序或其他导出器生成图表交付件。
- 可接受清晰度下仍超限时，说明瓶颈和已尝试的措施，由用户决定后续处理；不自行拆页、删素材、裁掉内容或更换导出器。

## 已核对的版本与证据

2026-10-18 静态核对的运行组合为：`@next-ai-drawio/mcp-server 0.4.6`、实际解析的 `@modelcontextprotocol/sdk 1.32.1`、随包 draw.io `v32.0.2`。版本分别来自两个包的 `package.json` 和 MCP 包的 `dist/drawio/.version`。以下容量数值来自源码核对，不能代替当前任务的实际试导出。

以下数值描述该组合的实现，不是所有版本、客户端、浏览器和部署方式的永久保证。MCP 包使用依赖版本范围，同一个 MCP 包版本也可能解析到不同 SDK；安装升级、改用外部 draw.io 或切换客户端后，应重新核对实际版本和相应源码。仓库 `main` 不能代替本机发布包的证据。

| 层次 | 核对结果 | 适用范围 |
| --- | --- | --- |
| MCP stdio 接收 | SDK 默认接收缓冲为 `10 * 1024 * 1024` 字节，即 10 MiB；本机服务未覆写该值。 | 服务器从 stdin 收到的完整 JSON-RPC 数据，包含工具名、参数、XML、Base64、转义和外层字段。它不是单张图片原文件的额度，也不是所有客户端共同的工具上限。 |
| 浏览器到 MCP 的 HTTP 请求体 | 服务端累加原始请求字节，超过 10 MiB 返回 HTTP 413。 | 包括整图同步和导出结果回传。整图同步可能同时携带 XML、SVG 预览及其他字段；导出回传包含 PNG/SVG 数据和外层 JSON。 |
| 工具 XML 参数 | 已核对的 `create_new_diagram`、`load_diagram`、`edit_diagram` 字符串参数没有额外声明固定最大长度。 | 不能据此认定无上限；仍受 stdio、客户端、浏览器、内存及后续整图同步限制。按对象分批调用只能降低单次请求体积。 |
| 正式图片导出参数 | `export_diagram` 暴露路径、格式、透明背景和页选择，没有宽度、高度或缩放参数。 | 不编造 `width`、`height`、`scale` 等工具参数。PNG 的浏览器导出调用默认使用 `scale: 2`，不能因此承诺固定输出尺寸。 |
| 随包 draw.io 的 PNG 导出 | embed PNG 导出没有指定宽度时，预计像素面积超过 `67,108,864` 会自动降低缩放。 | 这是该版本的面积预算和自动缩放逻辑，不是固定最大宽高，也不保证浏览器一定成功或结果满足清晰度要求。 |
| 工具截图 | 先尝试宽度 1000，再在结果超过 140,000 个 Base64 字符时尝试宽度 700。 | 140,000 是缩小截图的软阈值；第二次仍超出也可能返回。截图尺寸与正式 PNG 导出不同，不能用截图成功证明正式导出可行。 |

本机包内的可复核位置：

- MCP 包：`dist/index.js` 中的 `StdioServerTransport` 创建、工具参数定义与截图逻辑；`dist/http-server.js` 中的 `MAX_BODY_BYTES`、请求体读取和导出回传处理。
- SDK 包：`dist/esm/shared/stdio.js` 定义接收缓冲，`dist/esm/server/stdio.js` 应用默认值并处理接收溢出。
- MCP 包：`dist/preview/preview.js` 的 PNG 导出参数，以及实际使用的 shell 构建产物；随包 `dist/drawio/js/app.min.js` 的 `maxCanvasExportArea` 和 embed 导出自动缩放逻辑。行号随发布构建变化，应按上述符号与处理分支定位。

上游对照：[MCP 服务与安装说明](https://github.com/DayuanJiang/next-ai-draw-io/tree/main/packages/mcp-server)、[HTTP 实现](https://github.com/DayuanJiang/next-ai-draw-io/blob/main/packages/mcp-server/src/http-server.ts)、[工具实现](https://github.com/DayuanJiang/next-ai-draw-io/blob/main/packages/mcp-server/src/index.ts)、[draw.io v32.0.2 导出实现](https://github.com/jgraph/drawio/blob/v32.0.2/src/main/webapp/js/diagramly/EditorUi.js)。

## 插入前的预算与压缩

1. 读取素材的格式、原始字节数、宽高和透明通道，结合它在图中的实际使用尺寸处理副本。先保留必要内容与可接受清晰度，再选择压缩方式；处理后重新统计实际字节和尺寸，不只记录压缩参数。
2. 对原始 `n` 字节，标准 Base64 长度为 `4 * ceil(n / 3)` 个字符。图片被放入 Data URI、XML 属性和 JSON 后，还会增加前缀、属性、转义及外层字段。多个素材与图中其他内容共享同一请求和整图预算。
3. 估算完整序列化 JSON 的 UTF-8 字节数，例如在已有 Node.js 环境中计算 `Buffer.byteLength(JSON.stringify(payload), "utf8")`。stdio 预检应包含实际 JSON-RPC 外层；只能取得工具参数时，该结果只是部分体积，应计入尚未包含的开销，不能贴着已知上限发送。
4. 整图同步另算完整 XML 与相关附加字段。`.drawio` 可能以压缩格式保存，文件的磁盘字节数不能代表加载后的整图大小；`load_diagram` 会解压页面。紧凑 XML 展开、所有页面和嵌入图片也会增加实际内容。
5. 不用 `get_diagram` 回传文本的长度衡量真实整图大小。已核对版本在 `dist/embedded-images.js` 中把较长图片 Base64 折叠成 `embedded-image-…` 引用。引用只缩短工具回传，源图和传输中仍有真实图片数据；编辑时保留有效引用，不把它当成压缩结果。
6. 预计超过已知限制时先压缩素材副本，再重新计算。若仅单次请求过大，可在工具支持范围内按完整对象分批操作；每次仍发送完整有效对象，分批不解决累计整图或导出回传过大的问题。

不要把以上估算换成永久的“单图不得超过 X MB”规则。各层计算对象不同，最终 PNG 压缩率、SVG 内容、字体处理及浏览器内存也不能由素材原文件大小直接推出。预检用于发现明确风险，实际 MCP 导出才提供本次任务的运行证据。

## 插入后尽早验证 MCP 导出

在已有任务授权的目标会话中，插入大素材后尽早通过 `export_diagram` 试导出本次需要的格式，避免完成全部修改后才发现容量问题。试导出写入任务允许的工作目录，使用不覆盖已有交付件的临时路径；最终仍导出到约定位置。不要为试导出切换或覆盖另一幅尚未保存的图。

- `.drawio`：核对保存文件与当前完整文档对应，检查整图同步警告。导出成功但提示预览未响应、可能遗漏最新手动修改时，不能报告已保存最新状态。
- `.png`：记录 MCP 返回或实际文件中的字节和像素尺寸，检查素材是否完整、文字和细线是否仍清楚。截图可能已缩小，不能代替正式文件检查。
- `.svg`：核对真实文件体积和素材完整性；矢量格式仍可能包含较大的嵌入图片，且浏览器回传时可能使用 Base64，不能只按文件后缀推断容量。
- `.drawio.svg`：同时包含 SVG 和可重新加载的嵌入图 XML，应把两部分及编码开销计入预算，并核对预期页面与可编辑内容。传页选择参数可能只保存所选页，不能把单页结果覆盖成完整文档。

图片回传走同一个 HTTP 请求体检查。已核对版本的预览可能吞掉上传错误，工具最终只报超时，见 `dist/preview/preview.js` 的状态回传错误处理；不能只凭“超时”排除体积问题，也不能仅凭体积估算认定它就是容量问题。

远程图片需要单独核对：预览能看到网络图片不代表导出一定包含它。按任务已有授权取得可用素材副本，必要时压缩并嵌入，再检查最终所需格式中的素材完整性。遇到下载权限、访问或嵌入问题时说明实际限制，不用空白、旧图或缺素材的导出充当完整结果。当前上游还说明没有图片代理时，按网站地址插入的图片可能在导出中缺失，见 [上游素材与部署说明](https://github.com/DayuanJiang/next-ai-draw-io/tree/main/packages/mcp-server#self-hosted-drawio)。

## 有限恢复与重试

1. 连接、预览未打开或后台节流导致异常时，先恢复目标预览连接，再重试受影响的读取或导出一次。编辑已经成功而截图失败时，只补截图或导出，不重放编辑。
2. 有体积或分辨率风险时，根据实际统计压缩素材副本，通过 MCP 更新对应素材，再重试受影响的同步和导出一次。不要原样重复已知超限的请求。
3. 仍失败或可接受清晰度下仍超限时，保留已经成功保存的内容，说明已核对版本、失败格式、原始报错、可测体积或尺寸、已做的恢复与容量修正，以及哪些限制仍未知。交由用户决定后续处理，不自动拆页、删除素材或借用其他导出器。

客户端工具消息上限、当前浏览器能承受的最大宽高与内存、外部 draw.io 的设置，以及最终输出的编码体积，可能低于或不同于上述版本规则。没有当前证据时写明未知；不通过重复试错承诺始终可以导出。
